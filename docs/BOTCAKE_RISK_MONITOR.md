# Botcake 高危日志监控库：最终重构版

完整库代码：`botcake-risk-monitor.gs`；调用示例：`botcake-risk-monitor-caller.gs`。

## 使用

1. 在库项目中用完整 `.gs` 文件替换旧业务代码，不要与旧版重复粘贴。生产库不需要检测函数或其他旧脚本。
2. 填写开头默认配置中的 `SERVER_API_URL`、`SERVER_API_KEY`，支持 HTTP 和 HTTPS。也可在调用时分别传入自己的配置；有库查看权限的人可以看到库默认密钥，请据使用范围选择配置位置。
3. 发布库新版本，并将使用者项目的库引用切换到该版本。保存源码不会更新固定版本的引用。
4. 使用者从目标表格「扩展程序 → Apps Script」进入绑定项目，添加库并使用以下入口（库标识符以 `botcakeMsg` 为例）：

```javascript
function checkBotcakeRisks() {
  return botcakeMsg.checkBotcakeRisks();
}
```

调用方无需部署。手动运行并完成授权后，可自行添加指向本地入口的定时器；本库不创建、删除或更改触发器。超过本次运行预算会保存进度，下次调用继续，接续间隔由使用者的定时器决定。

自动获取调用者绑定的表格、文档属性和文档锁。不使用 Script Properties、Script Lock、缓存表格 ID 或 openById。无需传入表格 ID、存储对象、锁对象。仅面向表格绑定脚本；独立项目、Web App 不在此入口支持范围内。

## 默认配置和覆盖

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| PAGE_SHEET | botcake专页清单 | 专页输入 |
| RULE_SHEET | 日志类型控制 | B2:B 高危关键词 |
| RECORD_SHEET | botcake限制记录 | 告警和通知结果 |
| TIMEZONE | +8 | 香港时间显示，可改 +7 等 |
| API_TIMEZONE | +0 | Botcake 无时区时间按 UTC 解析 |
| SERVER_API_URL | 空 | 自建 Teams 发信接口 |
| SERVER_API_KEY | 空 | x-api-key |
| SEND_TEAMS | true | false 时只检查记录 |
| BATCH_SIZE | 10 | 每批 HTTP 请求数，1–20 |
| WRITE_EVERY_BATCHES | 5 | 累计批数后写表，1–50 |
| RETENTION_DAYS | 7 | 保留最近 7 天记录 |
| MAX_RUN_SECONDS | 240 | 每次执行预算，1–240 秒 |

```javascript
function checkBotcakeRisks() {
  return botcakeMsg.checkBotcakeRisks({
    PAGE_SHEET: 'botcake专页清单',
    TIMEZONE: '+8',
    SERVER_API_URL: 'http://your-server/send',
    SERVER_API_KEY: '你的密钥'
  });
}
```

只覆盖已知业务配置；undefined 沿用默认值，false、空字符串保留。每次断点接续需传入相同业务配置；不会记住上次的参数。手动建立触发器时选择本地包装入口。

密钥优先级：本次显式传入值 > 当前库文档属性 `BOTCAKE_TEAMS_API_KEY` > 库默认配置。建议用默认配置或显式参数；文档属性不是项目设置中的脚本属性。缺少通知地址或密钥时仍扫描记录，但不发送，H1 会体现未通知数量。

## 表格约定

第一行表头动态识别，顺序可变。缺失或重复必要表头会报错。

专页清单：`token`、`专页ID`、`名字`、`通知组ID`。缺 Token 或专页 ID 的行跳过；重复专页 ID 报错。ID 建议保存为纯文本。名字为空可检查；群 ID 为空只记录告警。

日志类型控制：读取 B2:B 非空关键词，普通包含匹配，不区分英文字母大小写，不作为正则。匹配最近 24 小时日志的“代码/子代码-说明”，不匹配时间和专页名字。空规则清单会报错。

限制记录：`专页ID`、`名字`、`通知组ID`、`高危日志`、`全部报错日志`、`更新时间`、`是否通知`。不存在时自动创建。H1 固定保存本轮最终总结果，不可用作业务表头。

- 高危日志：命中的控制表关键词，去重后换行分隔。
- 全部报错日志：最近 24 小时返回日志，格式为 `代码/子代码-错误说明-最新时间`，最新在前；超过单元格安全长度会截断并注明。
- 更新时间：告警首次记录时间，包含明确时差；重复命中不刷新。
- 是否通知：初始空白，仅接口成功接受后批量写“已通知”。不写其他状态、不写检查备注或通知备注。
- H1：整轮检查成功/失败、跳过、新增告警及通知结果；只在整轮结束写一次，暂停保留上一轮结果。

## 执行和防重复

1. 初始化：文档锁避免同表重叠执行，读取配置、清单、规则、历史与断点。断点按表格 ID 和三个工作表名区分。
2. 扫描：固定本轮最近 24 小时窗口，按批调用 Botcake。个别专页请求失败计入汇总，下轮重新检查，不阻塞其他页。
3. 提交：每累计若干批合并追加记录；先写表并 flush，再保存游标。正常暂停或结束前提交剩余缓冲。异常中断后可能重新读取未提交批次，已有记录继续去重。
4. 通知：全部专页尝试检查完且记录提交后，才按群合并通知。同群一条 HTML 消息，按名字自然排序，含专页 ID、高危关键词和具体日志。没有自动拆分消息。
5. 收尾：写 H1、清除完成断点，再按连续行分组从底部删除早于 7 天的记录。边界当天保留，中途暂停不删行。

相同“专页 ID＋排序后的高危关键词集合”在 24 小时内不重复记录。集合改变产生新告警；仅日志次数、顺序、最新时间改变不产生新告警。不要在执行期间排序、增删记录行；输入或规则变化会重新开始扫描，历史去重继续生效。

发送保护以一次群消息分块保存到文档属性：每块最多 128 个告警摘要，约 6 KB，不保存 Token 或消息正文。发送前保存 attempted，响应后保存结果；成功落表后删除相应保护块。1000 条同群告警需两次批量属性保存、8 次属性删除。

API 返回 2xx 且未明确返回 success:false、ok:false 或 error 时视为接口接受；不等于验证 Teams 实际送达。接口成功但写表中断，下次只补写“已通知”。超时、失败或结果未知时保留保护，不自动重发，以避免重复通知；过期保护在后续调用中清理。需要人工重试时先核对实际消息和服务端日志。

通知携带 Idempotency-Key，但只有服务器实现去重时才有服务端幂等保障。本脚本无法保证外部接口和表格写入的原子性。只处理“是否通知”为空的记录，旧的“未通知”等文字不自动兼容。

## 写入次数与性能

默认 1000 页全部命中、无中途暂停、一个群：20 次追加＋1 次通知状态写入＋1 次 H1＝22 次内容写入。没有新增和待通知记录时只写 H1。首次建表、格式设置、flush、过期行删除另计；这不是底层网络请求次数。

每次执行只读取一次限制记录，扫描和通知复用内存数据。发送保护统一读取，按块保存清理。没有逐页写备注或逐记录保存发送属性。1000 页一轮仍需要约 1000 次 Botcake 请求；实际定时频率需结合账号配额、执行耗时及通知大小限制。

## 升级注意

旧公共 Script Properties 不读取、不迁移；旧版若有实际已发送但未标记成功的记录，升级前先核对并补写“已通知”。若从曾经显式传入调用者属性的版本升级，发送保护也可能位于不同作用域，应先让旧版完成并核对未确认发送。保留历史表记录，不清空近 24 小时去重依据。

新版只接受当前断点和发送保护结构，无旧格式回退。配置或保护结构异常时明确报错。不要为绕过提示删除未确认的发送保护。

## 验证范围

真实 Google 测试已验证：库无参数取得当前表格、文档属性读写、两张表同名属性隔离、同表并发锁互斥和跨表锁独立。详情见 `BOTCAKE_LIBRARY_CONTEXT_VERIFICATION.md`。测试使用同账号、两个绑定项目、测试库 HEAD 和编辑器手动执行。

最终重构版另通过 `node scripts/test-botcake-risk-monitor.cjs` 本地模拟回归：1000 页、动态表头、24 小时去重、通知排序、暂停恢复、写表失败恢复、未知发送抑制、分块保护、7 天清理、配置与断点校验。最终代码未直接发布到生产库，未运行真实业务通知，也未实测不同账号与时间触发器。
